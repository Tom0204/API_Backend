## Décisions validées

| # | Question | Décision |
|---|---|---|
| D1 | Forme de `GET /api/v1/zones/:zoneId/monsters` | Route protégée, triée par niveau : `[{ id, code, name, level, stats: { hp, attack, defense, speed }, xpReward }]`, sans le butin |
| D2 | Forme d'un combat | `{ id, characterId, monsterId, status, character: { hp, maxHp, attack, defense, speed }, monster: { name, hp, maxHp, attack, defense, speed }, lastTurn: { characterDamage, monsterDamage } \| null, createdAt, finishedAt }` ; `lastTurn` seulement en réponse à une action ou à un démarrage où le monstre commence |
| D3 | Stockage du combat | Table `combats`, une colonne par statistique figée, CHECK (PV entre 0 et maximum), index unique partiel sur `character_id` WHERE `status = 'IN_PROGRESS'` en plus du verrou sur le personnage |

Choix d'implémentation (imitation de `docs/architecture.md`) :

- Dégâts : fonction pure `domain/combat/damage.ts` ; constantes `DEFENSE_CONSTANT` et `MIN_DAMAGE` de `game-rules.ts`.
- Propriété d'un combat vérifiée par son personnage (référence par identifiant), sans dupliquer le compte.
- Aucune restriction de niveau entre personnage et zone : aucune règle de `rules.md` n'en définit.
- Mana non figé dans le combat : inutilisé au MVP (rules.md §1, §3).
- Le contrôle de propriété passe avant `COMBAT_FINISHED` : un combat terminé d'un autre joueur répond aussi 404.
- `CHARACTER_NOT_FOUND` en 422 (personnage désigné dans le corps) : `characterErrors.notFoundInBody()`, même code et même message que le 404.
- `MonsterTemplate.combatStats` expose les statistiques au format de `domain/combat` : dépendance `world → combat` limitée à un type.
- Migration `20261126090000_combats` relue, appliquée à `mmorpg_dev` (aucun compte, aucun personnage) ; `prisma migrate diff` ne signale ensuite aucun écart.
