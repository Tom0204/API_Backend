## Décisions validées

| # | Question | Décision |
|---|---|---|
| D1 | Forme de `GET /api/v1/classes` | `[{ id, code, name, baseStats: { hp, mana, attack, defense, speed }, statsPerLevel: { hp, mana, attack, defense, speed } }]`, triées par nom |
| D2 | Forme d'un personnage (création, liste, détail) | `{ id, name, classId, zoneId, level, experience, createdAt }` ; liste triée par `createdAt` |
| D3 | Forme de `GET /api/v1/characters/:characterId/stats` | `{ characterId, level, experience, experienceToNextLevel (null au niveau 10), stats: { maxHp, currentHp, maxMana, currentMana, attack, defense, speed } }` |

Choix d'implémentation (imitation de `docs/architecture.md`) :

- Nom conservé avec sa casse ; unicité sur `lower(name)` (index de la migration initiale), P2002 → `CHARACTER_NAME_TAKEN`.
- `findByIdForUpdate` et `save` du repository des personnages ajoutés quand un cas d'usage s'en sert (L3/L4).
- Gain d'XP non entier, < 1 ou non sûr : invariant violé (500) ; aucune route ne l'appelle.
- Zone de départ résolue au démarrage par `STARTING_ZONE_CODE` ; absente → arrêt avec un message clair.
- `experienceToNextLevel` (D3) = XP **restante** pour passer au niveau suivant, pas le total du palier.
- Contrôle de propriété commun au détail et aux statistiques : `application/characters/find-owned-character.ts`.
- Paramètres de route typés par `characterParams.parse(req.params)` (déjà validés) : aucun transtypage.
- Le fake en mémoire reprend les classes du seed (`CHARACTER_CLASSES`) : une seule source pour les valeurs.
